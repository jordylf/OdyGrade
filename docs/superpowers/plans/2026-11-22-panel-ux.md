# Panel UX Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the OdyGrade panel into a panel-first, readable, responsive layout with an always-visible action bar.

**Architecture:** Restructure `index.html` keeping every element id, rewrite `src/style.css` with three width-based layouts, and add a small step-status function in `src/app.js`. A Node stdlib test pins the DOM contract and readability rules.

**Tech Stack:** Plain HTML/CSS/ES5-style JS (CEP 11 / Chromium ~88), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-22-panel-ux-design.md`

## Global Constraints

- No change to grading, engine, native recipe, effect params or host bridge (`src/engine.js`, `src/film.js`, `src/native-recipe.js`, `src/bridge.js`, `host/`, `native/`).
- No new dependencies, no framework, no inline scripts/styles (CSP).
- No CSS container queries; media queries on panel width: narrow `< 640px`, medium `640-1099px`, wide `>= 1100px`.
- Minimum text 11 px; interactive controls at least 28 px tall.
- Every existing element id stays (list in Task 1).

## Review Focus

- Very narrow dock (300-360 px): no horizontal scroll; action bar buttons wrap, not overflow.
- Short dock height (~500 px): action bar stays visible; content scrolls under it, last control not hidden behind it.
- Steps folded: keyboard focus still reaches every control once unfolded; `<summary>` is focusable.
- Before any frame is loaded: action bar buttons stay disabled (existing JS), step summaries read "Not loaded".
- Browser preview (no Adobe host): `#host` badge and `applyNative` still behave as today.
